# Content Management System

Digital Observatory uses **Keystatic** as a visual editor over the Markdown repository.

## Why this design

The CMS is deliberately Git-native:

- Markdown remains portable.
- Every edit has a Git history.
- Contributors can review changes as ordinary diffs.
- Content can be edited without a database migration.
- The website can be rebuilt from a repository clone.
- AI agents can understand the same content contract as humans.

Keystatic supports local storage for development and GitHub storage for collaboration and deployed editing. urlKeystatic configuration docshttps://keystatic.com/docs/configuration

## Local editing

Set:

~~~text
KEYSTATIC_STORAGE=local
~~~

Run:

~~~bash
npm run dev
~~~

Open /keystatic.

## GitHub-backed editing

For a deployed CMS:

~~~text
KEYSTATIC_STORAGE=github
KEYSTATIC_GITHUB_REPO=SH20RAJ/digital-observatory
~~~

Configure the GitHub App values generated by Keystatic:

- KEYSTATIC_GITHUB_CLIENT_ID
- KEYSTATIC_GITHUB_CLIENT_SECRET
- KEYSTATIC_SECRET
- NEXT_PUBLIC_KEYSTATIC_GITHUB_APP_SLUG

Keystatic GitHub mode authenticates editors through GitHub and restricts access to people with write access to the repository. urlKeystatic GitHub modehttps://keystatic.com/docs/github-mode

## Article workflow

1. Create an article in the CMS.
2. Fill in the SEO description and excerpt.
3. Add category and tags.
4. Add the author identity.
5. Add a cover image or let the site generate a poster.
6. Add every important source.
7. Set status to draft until editorial review is complete.
8. Publish by changing status to published.
9. Let the six-hour workflow build the accumulated changes.

The site excludes drafts and noIndex articles from public archives and the sitemap.

## Article poster system

If coverImage is empty, the website generates a 1200×630 article poster at /og/{slug}.

The poster is also used for social metadata and article previews. Next.js supports programmatic Open Graph images through its metadata system. urlNext.js Metadata and OG Imageshttps://nextjs.org/docs/app/getting-started/metadata-and-og-images

## Source contract

Every research article should have at least one direct, inspectable source for each important factual claim.

Preferred hierarchy:

1. Official project or government source.
2. Official API, repository, registry, standard, paper, or dataset.
3. Reputable specialist publication.
4. Secondary reporting only when it adds information unavailable from the primary source.

Sources & further reading is rendered below every article and is also surfaced in Article JSON-LD when available.

## Contributors

Contributors do not need CMS access to help.

A normal contributor can edit content/posts/*.md, open a pull request, and let CI validate the article. Maintainers can merge when ready.

For larger editorial projects, contributors can work in GitHub branches and use Keystatic locally.
